我建議你今天參加 Product Backlog Refinement 時，採取一個原則：

有被問到就回答自己負責範圍內的問題；沒有被問到，就不用主動扛起 FE Leader 的角色。

你是 FE Engineer，不是 FE Tech Lead。Clover 不在場，不代表今天所有前端決策都自動轉到你身上。

## 今天遇到不同情況，怎麼處理？

| 情況                   | 建議做法                                |
| -------------------- | ----------------------------------- |
| 沒有人問你 FE 的問題         | 不必刻意發言，先聽需求、了解規格。                   |
| 問到你熟悉的 API、實作細節或技術限制 | 根據你掌握的資訊回答。                         |
| 問到 UI 設計或 UX 規格      | 說明目前 Figma 或規格已確認的內容；不確定的地方請 UX 確認。 |
| 問到 FE 要怎麼分工、誰負責實作    | 不要直接替團隊承諾，先確認負責人。                   |
| 要你當場決定共用元件或架構方向      | 如果涉及團隊層級的設計決策，先記錄問題，等 Clover 回來再確認。 |
| 有人要求你直接承接整個 UI 功能    | 先釐清範圍、優先順序與負責人，不要因為現場沒人就直接答應。       |

## 如果 UI 問題真的丟給你，可以怎麼說？

1. 技術問題，你可以回答

「這部分我可以先從目前的 FE 實作方式說明。」

2. 設計規格尚未確認

「這部分我想先跟 UX 確認一下，避免我們對 UI 行為的理解不一致。」

3. 涉及 FE 分工或共用元件

「這部分可能會涉及 FE 團隊的分工，我先記錄下來，等 Clover 回來再一起確認。」

4. 現場要求你直接承諾時程

「我需要先確認需求範圍和目前的工作優先順序，再評估實作時程。」

## 我認為你今天最適合的定位

不是完全沉默，也不是主動接管，而是：

* 提供資訊：你知道的就說清楚。

* 指出不確定性：規格未定就明確標示。

* 不代替別人做決策：尤其是 FE 分工、共用元件與時程承諾。

你可以積極參與討論，但不需要因為 FE Leader 不在，就把原本不屬於你的責任全部接過來。

今天的目標是讓需求更清楚，不是證明你能代替 FE Leader。
