# 什麼是視差滾動（Parallax Scrolling）？

視差滾動是一種網頁視覺設計技術，英文稱為 Parallax Scrolling。

簡單來說：

當使用者往下捲動網頁時，畫面中不同的元素以不同的速度移動，產生遠近層次與空間深度的視覺效果。

它模仿的是我們在現實世界中看到的視差現象。

例如，你坐在行駛中的火車上：

- 近處的電線桿，看起來移動得很快。
- 中距離的房屋，移動得比較慢。
- 遠處的山，看起來移動得非常慢。

這就是視差（Parallax）的概念。

## 1. 視差滾動是怎麼運作的？

一般網頁的元素通常會跟著頁面捲動，以相同的捲動規律移動。

視差滾動則是讓不同元素具有不同的移動速度。

假設網頁有三個圖層：

| 圖層 | 元素    | 移動速度 |
| -- | ----- | ---- |
| 前景 | 樹木、人物 | 快    |
| 中景 | 房屋、建築 | 中    |
| 背景 | 山脈、天空 | 慢    |

當使用者往下捲動時，三個圖層的移動速度不同，就會產生立體感。

[youtube.com](https://www.youtube.com/watch?v=2z4OTRFuLP8\&utm_source=chatgpt.com)

從前端實作角度來看，常見方式包括：

- CSS `background-attachment: fixed`
- CSS `transform: translateY()` 搭配捲動進度
- JavaScript 監聽 scroll 事件
- 使用 Intersection Observer 搭配動畫
- 使用 GSAP ScrollTrigger 等動畫工具

不過，這些方法的實作能力和效果不同，並不是所有方法都能做到真正的多圖層視差。

## 2. 為什麼要使用視差滾動？

視差滾動不是單純為了讓網頁看起來比較炫，而是有幾個設計目的。

### ① 增加視覺深度

傳統網頁比較像平面文件，元素按照上下順序排列。

視差滾動可以讓畫面呈現前景、中景、背景的空間關係，增加立體感。

### ② 引導使用者的注意力

透過元素移動、出現和消失的時機，可以引導使用者注意特定內容。

例如：

- 產品圖片隨著捲動逐漸放大。
- 標題在特定位置出現。
- 背景圖片緩慢移動，前景文字保持穩定。

### ③ 增加故事敘述能力（Storytelling）

這是視差滾動很重要的應用。

一般網頁是讓使用者閱讀內容；視差滾動則可以讓使用者透過捲動，逐步經歷一段視覺故事。

例如：

1. 第一幕：介紹產品。
2. 第二幕：產品拆解。
3. 第三幕：展示內部技術。
4. 第四幕：呈現產品完整樣貌。

使用者的捲動行為就像在控制故事的播放進度。

### ④ 增加互動體驗與記憶點

適當的動畫能讓使用者更有參與感，也能讓品牌或產品介紹更令人印象深刻。

但要注意：動畫多不代表體驗好。

## 4. 什麼時候不適合使用視差滾動？

視差滾動不是每個網站都適合。

以下幾種情況，反而可能造成反效果。

| 網站類型              | 不適合的原因          |
| ----------------- | --------------- |
| 後台管理系統（Dashboard） | 使用者重視效率、資訊密度與操作 |
| CRUD 管理介面         | 增加不必要的視覺干擾      |
| 表格、資料列表           | 需要快速瀏覽、搜尋與比較資料  |
| 文件、技術文件網站         | 使用者主要目的是閱讀與查找資訊 |
| 電商商品列表            | 可能影響商品瀏覽與購買效率   |
| 內容非常長的文章          | 動畫可能干擾閱讀節奏      |

例如，你目前開發的 Supermicro SCC 管理系統：

使用者主要任務是管理 Compute、檢視硬體資訊、操作 Drawer、搜尋資料等。

這種情境下，視差滾動通常沒有實質價值。

使用者希望的是：

- 快速找到資料。
- 清楚理解資訊。
- 順利完成操作。
- 不要因為動畫而等待。

所以不應為了視覺效果而增加視差動畫。

## 5. 使用視差滾動需要考慮哪些問題？

即使是適合的網站，也不代表可以毫無限制地使用。

| 考量因素   | 可能產生的問題             |
| ------ | ------------------- |
| 效能     | 過多動畫造成 CPU/GPU 負擔   |
| 手機裝置   | 小螢幕與觸控操作可能不適合某些效果   |
| 使用者體驗  | 動畫過多會造成視覺疲勞         |
| 無障礙    | 部分使用者可能對移動動畫敏感      |
| SEO    | 不應讓重要內容依賴動畫才出現      |
| 瀏覽器相容性 | 部分 CSS 效果在不同瀏覽器表現不同 |

特別建議：

- 優先使用 CSS `transform` 和 `opacity` 做動畫。
- 支援 `prefers-reduced-motion`，尊重使用者減少動態效果的設定。
- 不要讓動畫阻礙使用者閱讀或操作。
- 手機版可以考慮簡化或取消視差效果。

## 6. 視差滾動與一般 Scroll Animation 有什麼不同？

這兩個概念容易混淆。

| 比較         | Parallax Scrolling | Scroll Animation |
| ---------- | ------------------ | ---------------- |
| 中文         | 視差滾動               | 捲動動畫             |
| 核心概念       | 不同圖層以不同速度移動        | 元素隨捲動觸發動畫        |
| 主要目的       | 建立空間深度             | 呈現動態效果           |
| 常見效果       | 前景、中景、背景不同速度       | 淡入、滑入、放大、縮小      |
| 是否一定要有不同速度 | 是，這是典型視差的核心        | 不需要              |

這就結合了 Parallax Scrolling 和 Scroll Animation。

## 7. 最後：如何判斷是否應該使用視差滾動？

我會用以下四個問題判斷：

## 視差滾動使用判斷

1. 網站是否重視視覺體驗？

   如果網站重視品牌形象、故事敘述、產品展示，可以考慮。
2. 視差效果是否有助於傳達資訊？

   如果只是為了炫麗，沒有實際傳達價值，就不一定需要。
3. 是否會影響使用者完成主要任務？

   如果會降低閱讀、搜尋或操作效率，就不應使用。
4. 是否能兼顧效能與無障礙？

   如果無法提供流暢、可控制的體驗，就應簡化效果。

我的核心觀念是：

視差滾動是一種設計手段，而不是設計目的。

使用它的理由，應該是它能幫助網站更好地傳達資訊、呈現故事或創造體驗，而不是因為它看起來很酷。

## 8. 如果你想研究視差滾動，我建議這樣開始

可以把研究分成三個階段：

1. 觀察與理解：收集 3～5 個使用視差滾動的網站，分析它們為什麼使用、使用在哪裡。
2. 拆解效果：觀察背景移動、前景移動、圖片縮放、文字進場等效果。
3. 實際實作：先用 HTML、CSS、JavaScript 做一個簡單的三圖層視差效果，再逐步增加複雜度。

我會特別建議你先不要急著寫程式。

先去觀察不同網站的設計，思考：

「如果拿掉這個視差效果，這個網站會失去什麼？」

這個問題能幫助你從單純學習動畫技術，進一步理解網頁設計背後的目的。

這也會讓你學到的不只是怎麼實作 Parallax Scrolling，而是什麼時候應該使用它。
