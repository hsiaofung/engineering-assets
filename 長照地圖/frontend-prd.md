# 長照機構搜尋 App — 頁面流程 PRD
（以使用者旅程為核心、前端頁面規格）

## 1. 專案概覽

本專案是一個無登入、無狀態的簡單網頁應用，幫助正在面對父母可能失智或需要長期照顧的家庭照顧者，快速找到附近合適的長照機構。使用者只需輸入家庭地址，系統即依距離由近到遠排序，以卡片形式呈現機構，點擊後可查看評價、聯絡方式與詳細服務資訊。

目標使用者為一般家庭照顧者，主要目標是在情緒可能較焦慮的當下，用最少步驟獲得「最近、可聯絡、服務清楚」的機構資訊。關鍵商業目標是驗證「距離優先 + 服務透明」的核心價值是否能真正幫助使用者做出下一步行動（撥打電話或实地探訪）。成功指標暫以「使用者成功進入詳情頁並產生撥打／分享意圖」為主。

整個體驗強調乾淨、直接、溫柔，避免任何多餘干擾，完全聚焦於「輸入地址 → 看到最近機構 → 取得聯絡方式」這條最短路徑。

## 2. 使用者類型與權限

本 MVP 僅有單一使用者類型：一般家庭照顧者。

- 無需註冊或登入
- 無任何權限分級或角色差異
- 所有功能對所有訪客開放
- 無個人化資料儲存，每次使用皆為全新狀態

此設計大幅降低使用門檻，讓使用者在最需要幫助的當下可以立即開始，不必先建立帳號。未來若需擴充收藏或比較功能，可再引入輕量帳號系統，但目前完全不在範圍內。

驗證／授權考量：無。所有頁面皆為公開存取。

## 3. 導航與資訊架構

採用極簡導航策略，符合「單一核心流程」的產品定位。

主要導航結構：
- 首頁（/）：僅有地址輸入區與搜尋按鈕
- 結果列表頁（/results）：顯示搜尋結果
- 機構詳情頁（/facility/:id）：單一機構完整資訊

次要導航：無側邊欄、無底部導航列、無漢堡選單。

路由層級：
- / → 首頁
- /results?address=xxx → 結果列表（地址以 query 傳遞）
- /facility/:id → 詳情頁

麵包屑策略：不使用傳統麵包屑。改以頂部簡易提示列顯示「目前搜尋：台北市大安區復興南路…」＋返回按鈕，讓使用者隨時知道自己的位置並可快速返回。

搜尋功能：僅首頁提供地址輸入，結果頁不提供即時篩選（符合 MVP 範圍）。

行動裝置導航差異：
- 頂部欄在手機上固定，返回按鈕足夠大以方便觸控
- 詳情頁返回後回到結果列表的相同滾動位置（若技術可行）
- 無底部導航，最大化內容顯示空間

## 4. 核心使用者流程

### 流程名稱：尋找附近長照機構
進入點：使用者開啟 App 首頁  
先決條件：無（任何人皆可使用）

步驟：
1. 使用者進入首頁，看到清楚的地址輸入欄與「尋找長照機構」按鈕 → 系統顯示乾淨、聚焦的輸入介面
2. 使用者輸入或貼上家庭地址 → 系統即時驗證格式（基本檢查）
3. 使用者按下「尋找長照機構」→ 系統顯示簡短載入狀態，計算距離並排序
4. 系統進入結果列表頁，依距離由近到遠顯示機構卡片 → 使用者可快速掃視
5. 使用者點擊任一張卡片 → 系統導向該機構詳情頁
6. 使用者在詳情頁查看評價、服務、地圖預覽，並可一鍵撥打、複製地址或分享 → 系統觸發對應系統功能
7. 使用者按下返回 → 回到結果列表頁

成功狀態：使用者成功取得機構聯絡方式並產生撥打或分享行為。

錯誤情境：
- 地址無法解析 → 顯示溫柔提示並請重新輸入
- 附近無機構 → 進入空狀態
- 網路異常 → 顯示重試按鈕

替代路徑：使用者可在結果頁或詳情頁隨時返回首頁重新搜尋。

## 5. 詳細頁面規格

### 頁面名稱：首頁
路由：/  
目的：讓使用者用最少認知負擔輸入地址並啟動搜尋  
使用者存取：所有人

版面結構：
- 頁首：簡潔 Logo 或產品名稱
- 主要內容：置中大標題「找到附近適合的長照機構」+ 地址輸入欄 + 主要 CTA 按鈕
- 側邊欄：無
- 頁尾：簡短說明「資料僅供參考，請以實際聯絡為準」

ASCII 線框：
```
┌─────────────────────────┐
│  Logo / 產品名稱         │
├─────────────────────────┤
│                         │
│   找到附近適合的         │
│   長照機構               │
│                         │
│  ┌───────────────────┐  │
│  │ 輸入家庭地址...    │  │
│  └───────────────────┘  │
│                         │
│  [ 尋找長照機構 ]       │
│                         │
│  資料僅供參考...        │
└─────────────────────────┘
```

主要顯示資料：無  
使用者操作：輸入地址、按下搜尋  
互動：輸入時即時基本驗證；按鈕在地址空白時禁用  
狀態變化：
- 載入中：按下後按鈕顯示載入中
- 空狀態：無
- 錯誤：地址格式錯誤時顯示提示文字
- 成功：導向結果頁

行動裝置考量：輸入欄與按鈕佔滿寬度，鍵盤彈出時頁面自動調整。  
邊界情況：使用者貼上過長地址、使用定位權限（未來可加）。

### 頁面名稱：結果列表頁
路由：/results  
目的：依距離排序呈現機構，讓使用者快速比較  
使用者存取：所有人

版面結構：
- 頁首：返回按鈕 + 目前搜尋地址提示 + 「重新搜尋」文字連結
- 主要內容：垂直卡片列表
- 側邊欄：無
- 頁尾：無

ASCII 線框：
```
┌─────────────────────────┐
│ ← 返回   目前：大安區... │
├─────────────────────────┤
│ ┌─────────────────────┐ │
│ │ [圖片] 機構名稱      │ │
│ │ 0.8 km  ★4.6  床位32 │ │
│ │ 服務：日照 失智專區  │ │
│ │ ⚠ 無居家服務         │ │
│ └─────────────────────┘ │
│ ┌─────────────────────┐ │
│ │ ...下一張卡片...     │ │
│ └─────────────────────┘ │
└─────────────────────────┘
```

主要顯示資料：
- 機構名稱與圖片
- 距離（km）
- 平均評分
- 床位／服務人數
- 主要服務標籤
- 未提供服務的醒目標示

使用者操作：
- 點擊整張卡片 → 進入詳情頁
- 點擊「重新搜尋」→ 回首頁

互動：卡片有輕微按壓縮放回饋；長按無額外功能  
狀態變化：
- 載入中：骨架屏或置中載入指示
- 空狀態：溫暖插圖 +「附近暫無符合的長照機構」+「重新輸入地址」與「擴大搜尋範圍」按鈕
- 錯誤：網路錯誤時顯示重試
- 成功：正常列表

篩選／排序：固定依距離由近到遠，無其他選項（MVP 範圍）  
行動裝置考量：卡片全寬，圖片比例固定，文字不溢出。  
邊界情況：只有 1 筆結果、結果超過 20 筆時採用分頁或「載入更多」。

### 頁面名稱：機構詳情頁
路由：/facility/:id  
目的：提供足夠資訊讓使用者決定是否聯絡  
使用者存取：所有人

版面結構：
- 頁首：返回按鈕 + 機構名稱
- 主要內容：圖片、基本資訊、服務列表、評價、聯絡區、簡易地圖預覽
- 側邊欄：無
- 頁尾：無

ASCII 線框：
```
┌─────────────────────────┐
│ ← 返回   陽光長照中心   │
├─────────────────────────┤
│ [大圖]                  │
│ 名稱  ★4.6 (128則)     │
│ 0.8 km · 床位 32        │
│ 適合失智症  開放時間... │
│                         │
│ 服務項目                │
│ ✓ 日照  ✓ 失智專區      │
│ ⚠ 無居家服務            │
│                         │
│ 評價摘要                │
│ 「環境乾淨...」         │
│                         │
│ [撥打電話] [複製地址]   │
│ [分享]                  │
│ [簡易地圖預覽]          │
└─────────────────────────┘
```

主要顯示資料：
- 機構名稱、圖片、距離、評分、床位
- 「適合失智症」標籤、開放時間
- 完整服務列表（有／無清楚標示）
- 評價摘要 + 3～5 則評論
- 電話、地址、官方網站
- 簡易地圖預覽

使用者操作：
- 撥打電話 → 觸發系統撥號
- 複製地址 → 複製到剪貼簿並顯示成功提示
- 分享 → 呼叫系統分享選單
- 點擊地圖預覽 → 可開啟外部地圖 App（若可行）

互動：主要按鈕有明確視覺層級；評價可展開更多  
狀態變化：
- 載入中：骨架屏
- 空狀態：無（資料必存在）
- 錯誤：資料載入失敗時顯示重試
- 成功：正常顯示

行動裝置考量：聯絡按鈕固定於底部或易於觸及位置，避免被鍵盤遮擋。  
邊界情況：無評價時顯示「尚無評價」；無網站時隱藏該按鈕。

## 6. 模擬資料策略

需要一份靜態模擬資料檔（例如 facilities.json 或 mockFacilities.ts）。

- 總筆數：40 筆
- 每筆關鍵欄位：id、name、imageUrl、address、phone、website、distanceKm、rating、reviewCount、bedCount、services[]（含是否提供）、missingServices[]、isDementiaFriendly、openingHours、reviews[]（3～5 則，含作者、評分、內容、日期）
- 資料分布：距離從 0.5 km 到 15 km 均勻分布；評分 3.2～4.9；約 40% 有失智專區；部分機構故意缺少特定服務以測試標示
- 關係：reviews 隸屬於 facility；所有資料為扁平結構，方便前端直接使用
- 產生方式：硬編碼 + 適度使用 faker 產生評論文字與名稱，確保中文真實感
- 模擬服務函式：getFacilitiesByAddress(address)、getFacilityById(id)，回傳已排序資料

## 7. 互動模式與微互動

- 詳情採用新頁面導向（非 Modal）
- 無內嵌編輯
- 無拖放
- 無即時更新（靜態資料）
- 通知／吐司：複製地址成功、分享成功時使用輕量吐司
- 確認對話框：無（撥打直接觸發系統）

## 8. 邊界情況與錯誤處理

- 所有頁面載入狀態：使用骨架屏或置中 spinner，避免空白閃爍
- 空狀態：溫柔文案 + 明確 CTA（重新輸入地址、擴大範圍）
- 表單驗證：地址空白時禁用按鈕；格式明顯錯誤時即時提示
- 錯誤訊息：使用溫暖、非技術性語言（「目前連線有點不穩定，請再試一次」）
- 網路失敗：提供重試按鈕
- 權限被拒：無（無定位強制需求）

## 9. 效能與 UX 考量

- 結果列表採用分頁或「載入更多」（每頁 10 筆），避免一次渲染過多卡片
- 圖片延遲載入
- 樂觀更新：無（無寫入操作）
