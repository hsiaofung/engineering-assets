# 成功頁面（Success Page / Success Message）重點整理

## 為什麼成功訊息重要？

表單成功提交後，使用者最想知道的是：

> 「我的資料有成功送出嗎？」

如果沒有明確回饋，使用者會：

* 不確定是否提交成功
* 重複點擊送出
* 懷疑系統是否故障
* 降低對產品的信任

因此成功訊息會影響：

* 客戶留存（Retention）
* 使用者忠誠度（Loyalty）
* 品牌信任（Trust）

---

# 成功訊息的核心目的

成功訊息需要告訴使用者：

1. **已完成（Completed）**
2. **接下來會發生什麼（Next Step）**
3. **系統正在處理什麼（Action Taken）**

---

## 不要讓使用者懸而未決

錯誤：

```text
Submit
```

然後沒有任何反應。

使用者會想：

* 有送出去嗎？
* 要不要再按一次？
* 我的資料去哪裡了？

---

好的：

```text
您的申請已成功送出。

我們會在 1–2 個工作天內與您聯絡。
```

---

# 成功頁面不只是通知

表單不是單純：

> 收集資料 → 寄 Email

而是一個：

> 使用者與產品建立關係的互動點。

使用者花時間：

* 閱讀
* 填寫
* 提交

產品應該回應：

> 我收到你的需求，而且正在處理。

---

# 成功訊息形式

成功回饋可以有不同方式：

## 1. 新頁面（Success Page）

例如：

提交後：

```
/contact/success
```

顯示：

```
Thank you!

您的訊息已送出。
```

適合：

* 註冊完成
* 購買完成
* 申請流程

---

## 2. AJAX 更新目前頁面

不離開頁面：

原本：

```
[表單]
```

提交後：

```
✓ 已成功送出
我們將盡快回覆您。
```

適合：

* 聯絡表單
* 搜尋
* 小型操作

---

## 3. Modal / Dialog

例如：

```
+----------------+
| ✓ Success      |
|                |
| 資料已更新     |
|       OK       |
+----------------+
```

適合：

* 快速操作
* 設定更新

---

# 成功訊息設計原則

## 1. 表達重視使用者輸入

提交後不要只是：

❌

```
Success
```

太冷漠。

---

更好：

✅

```
謝謝您的留言，我們已收到您的需求。
```

---

# 2. 告訴使用者下一步

成功訊息應回答：

> 接下來呢？

例如：

註冊：

```
帳號建立成功。

請檢查 Email 完成驗證。
```

---

聯絡：

```
您的問題已送出。

客服將於 24 小時內回覆。
```

---

購物：

```
訂單已成立。

配送資訊將寄送至您的 Email。
```

---

# 3. 提供明確確認

避免：

❌

```
Done
```

---

推薦：

✅

```
您的表單已成功提交。
```

包含：

* 動作
* 狀態
* 結果

---

# 成功訊息 UX Checklist

## 提交後

* ✅ 使用者知道成功
* ✅ 顯示成功狀態
* ✅ 說明下一步
* ✅ 告知處理時間（如果需要）
* ✅ 提供後續操作入口

---

# Accessibility 注意事項

成功訊息也需要無障礙。

例如 AJAX 更新：

視障使用者可能看不到畫面變化。

可以使用：

```html
<div aria-live="polite">
  表單已成功送出
</div>
```

讓 Screen Reader 知道：

> 有新的訊息出現。

---

# 成功頁面與錯誤訊息比較

|      | 錯誤訊息     | 成功訊息      |
| ---- | -------- | --------- |
| 目的   | 協助修正     | 確認完成      |
| 核心問題 | 哪裡錯？怎麼改？ | 完成了嗎？下一步？ |
| 語氣   | 協助       | 鼓勵與確認     |
| 位置   | 靠近錯誤欄位   | 提交後明確顯示   |

# Angular / Frontend 實務

Reactive Form：

流程：

```
Submit
 ↓
Validate
 ↓
API Request
 ↓
Success Response
 ↓
Show Success UI
```

例如：

```typescript
onSubmit() {
  this.api.submit(data)
    .subscribe(() => {
      this.showSuccess = true;
    });
}
```

UI：

```html
<div *ngIf="showSuccess"
     aria-live="polite">
  表單已成功送出，我們會盡快與您聯絡。
</div>
```

---

# 常見錯誤

## ❌ 沒有任何成功回饋

使用者不知道結果。

## ❌ 只顯示「Success」

資訊不足。

## ❌ 成功後直接清空表單

使用者可能懷疑：

> 我的資料是不是消失了？

## ❌ 沒說下一步

使用者不知道：

* 等多久
* 找誰
* 接下來做什麼

---

# 核心觀念（一句話）

> **成功訊息的目的不是告訴使用者「系統完成了一件事」，而是讓使用者確定「我的需求已被收到，並且知道接下來會發生什麼」。**
