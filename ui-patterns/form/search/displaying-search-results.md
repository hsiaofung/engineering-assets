# 顯示搜尋結果設計重點

## 1. 保留搜尋關鍵字 (Keep Search Query)

* 使用者進入結果頁後，原本輸入的文字應保留。
* 好處：

  * 使用者可以直接修改搜尋條件。
  * 避免重新輸入，提高操作效率。

---

## 2. 顯示搜尋結果數量 (Show Result Count)

* 告知使用者總共有多少筆結果。
* 幫助使用者判斷下一步：

  * 結果太多 → 使用篩選或排序。
  * 結果太少 → 修改搜尋條件。

例如：

> 找到 303 筆結果

---

## 3. 提供排序功能 (Sorting)

依資料類型提供常見排序方式：

* 相關性 (Relevance)
* 熱門程度 (Popularity)
* 最新時間 (Recency)
* 價格高低 (Price)

排序能幫助使用者快速找到最符合需求的項目。

---

## 4. 避免預設使用無限捲動 (Avoid Infinite Scroll)

無限捲動常造成：

* 使用者不知道總共有多少結果。
* 難以回到之前看過的位置。
* 不容易比較結果。

建議替代方案：

### 「顯示更多」(Load More)

適合：

* 社群內容
* 大量使用者產生內容
* 瀏覽導向情境

### 分頁 (Pagination)

適合：

* 電商
* 搜尋特定商品
* 需要比較與定位結果的情境

---

# 5. 選擇正確結果版面配置

搜尋結果主要有兩種呈現方式：

## List View (列表檢視)

適合：

> 使用者需要大量資訊比較

例如：

* 家電
* 軟體
* 服務
* 文件

特色：

* 可以呈現較多文字資訊：

  * 標題
  * 描述
  * 評論
  * 規格
  * 其他詳細資訊

設計原則：

* 遵循由左至右閱讀習慣。
* 最重要資訊放左側。
* 詳細資訊放右側。

範例：

```
[圖片] 商品名稱        價格
       描述            評價
       規格            其他資訊
```

---

## Grid View (網格檢視)

適合：

> 圖片是主要決策因素

例如：

* 服裝
* 家具
* 圖片素材

特色：

* 圖片為核心。
* 減少文字資訊。
* 使用者快速掃描多個選項。

設計原則：

* 一次約展示 4～6 個項目。
* 保留項目間距。
* 避免資訊過度堆疊。

---

# List vs Grid 比較

|       | List View | Grid View |
| ----- | --------- | --------- |
| 適合    | 詳細比較      | 視覺探索      |
| 重點    | 文字資訊      | 圖片        |
| 使用情境  | 家電、服務、文件  | 商品、圖片     |
| 顯示資訊  | 多         | 少         |
| 使用者行為 | 分析比較      | 快速瀏覽      |

---

# 6. 搜尋結果應支援篩選 (Filtering)

好的搜尋體驗通常包含：

## Filter

讓使用者縮小結果範圍，例如：

* 類型
* 顏色
* 價格
* 材質
* 地點
* 日期

目的：

> 減少選擇數量，降低使用者決策負擔。

---

# 7. 搜尋結果頁應提供多種操作

好的搜尋結果頁通常包含：

✅ 搜尋關鍵字
✅ 結果數量
✅ 篩選
✅ 排序
✅ 商品/內容資訊
✅ 比較功能
✅ 詳細頁入口

例如商品：

```
搜尋結果

303 筆結果

Filter:
☑ 類型
☑ 顏色
☑ 價格

Sort:
相關性 ▼


[圖片]
商品名稱
價格
顏色
快速查看

```

---

# 核心設計原則

> **搜尋不是結束，而是協助使用者完成決策的開始。**

好的搜尋結果頁應該：

1. 幫助使用者理解目前結果。
2. 幫助使用者縮小選擇範圍。
3. 提供足夠資訊比較選項。
4. 降低資訊過載與決策成本。

---

## 搜尋結果頁 Checklist

* ✅ 保留搜尋文字
* ✅ 顯示結果數量
* ✅ 提供排序
* ✅ 提供篩選
* ✅ 避免預設無限捲動
* ✅ 根據資料類型選擇 List/Grid
* ✅ 重要資訊放在符合閱讀習慣的位置
* ✅ 幫助使用者快速完成選擇而不是只展示資料
