# 對我還有一個問題，這三條skill是一次下下去。還是手動一個skill做完，手動換下一個?

這個問題問得很好。答案是：**兩種方式都可以，但我建議你採用「自動選擇、分階段執行」的方式。**

這裡要區分兩件事：

1. **Skill 的選擇**：由 AI 根據任務判斷需要哪些 Skill。
2. **Skill 的執行**：依照工作流程，一個階段接一個階段完成。

### **例如：開發一個 Compute System 頁面**

假設這個頁面同時需要 List、Tree、Actions 三種功能。

**你下達一次任務**

「幫我開發 Compute System 頁面」

**AI 分析需求**

判斷需要 List、Tree、Actions Skill

**List**

建立清單

**Tree**

建立導覽

**Actions**

建立操作

**整合與測試**

檢查三個功能之間的資料、狀態與事件是否正確整合

完成 Compute System 頁面

### **但實際開發時，我建議你不要讓 AI 一口氣全部寫完。**

可以讓 AI：

1. 先使用 List Skill，完成後檢查。
2. 再使用 Tree Skill，完成後檢查。
3. 再使用 Actions Skill，完成後檢查。
4. 最後整合、測試。

你只需要下達一次任務，但 AI 分階段執行。重要的架構決策或不確定事項，先停下來詢問你。

### **這裡還有一個技術細節**

Skill 不一定會自動全部載入。

例如某些支援 Skill 的 AI 工具會根據 Skill 的描述和觸發條件，判斷要不要載入；有些則需要你明確指定。這取決於你使用的平台。

**我想建議你再往前走一步：**

未來你甚至可以建立第四條 Skill，叫做 `angular-page-orchestrator`。

它不負責寫 List、Tree 或 Actions，而是負責：

- 分析需求
- 判斷需要哪些 Skill
- 安排執行順序
- 整合不同 Skill 的成果
- 驗證最後的頁面

這就像一個工程主管，負責調度不同專業的工程師。

你不再只是教 AI 寫程式，而是開始教 AI 如何組織一個開發團隊。
