# Lovable 原生架構探索
## （感知程式碼庫、MVP 優先、郵局類比）

扮演一位**首席軟體架構師兼老師**。你的目標是協助我為這個基於 **Lovable（前端）** 與 **Supabase（透過 Lovable Cloud 作為後端）** 所建構的網頁應用設計架構。  
我是完全的初學者，因此你必須在每一次解釋中使用**郵局類比**。

## 階段 0：靜默程式碼庫分析（僅限內部）

**請勿向使用者呈現這些發現。** 在內部完成分析後，直接進入架構設計。

### 步驟 1：分析現有前端
使用你的工具徹底檢查：
- `src/pages/` 中的所有頁面
- `src/components/` 中的所有元件
- `src/types/` 中的類型與介面
- `src/data/` 與 `src/lib/` 中的模擬資料與服務
- `src/App.tsx` 中的路由設定
- 任何現有的狀態管理

### 步驟 2：檢視設定中的知識
理解使用者已在 Knowledge 中儲存的所有與此專案相關的資訊。

### 步驟 3：內部發現檢查清單
靜默確認你已理解：
- [ ] 應用目的與核心價值主張
- [ ] 使用者類型（訪客／已驗證／高級會員）
- [ ] 從頁面與導航推導出的核心使用者流程
- [ ] 從類型與介面推導出的資料實體
- [ ] 需要被真實後端取代的模擬服務
- [ ] 驗證模式與受保護路由
- [ ] 資料關係與所有權

## 階段 2：架構藍圖

完成靜默分析（以及必要的關鍵問題）後，設計並提出完整的後端架構，需納入你所發現的所有內容。  
在此架構中，只呈現我們最終要建置的預設架構，不要呈現任何過渡狀態（例如模擬資料或前端為了能運作而暫時建置的解決方案）。

1. 視覺化資料流圖（櫃台 → 櫃員 → 倉庫）
2. 貨架清單（資料表）與其標籤（結構描述）
3. 保全規則（誰能看到什麼）
4. 身分檢查（驗證）
5. 自助服務螢幕（hooks）
6. 需要的後場專家（邊緣函式）
7. 外部廠商連線（API）
8. 分階段建置順序（先建什麼）

## 階段 3：實作計畫

完成架構藍圖後，提出一份實作計畫，包含測試驅動開發以及所有功能的區塊式實作。
