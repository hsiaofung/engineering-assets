# 反過來如果對方出卡住的問題，我也不會呢?

這個問題更有意思了！因為現在角色互換了。

剛剛是你問對方：「你遇到什麼困難？」

現在對方告訴你問題，但你也不會。

這時候，其實正好可以實踐同一套原則。

## **一、承認自己不知道，不需要覺得丟臉**

例如對方說：

「這個問題是 Angular 底層的 change detection 機制造成的。」

你不知道。

可以回答：

「這部分我還不太熟，我們一起研究看看。」

或者：

「這個我目前沒有答案，我先查一下相關資料，再跟你討論。」

這不是能力不足，而是誠實面對自己的知識邊界。

## **二、不要把不知道變成不負責任**

這裡有三種不同的反應：

| 反應              | 實際傳遞的訊息     |
| --------------- | ----------- |
| 我不會啊            | 我不打算處理      |
| 我不會，你問別人        | 我把問題交出去     |
| 我目前不會，但我願意一起找答案 | 我承認限制，也願意承擔 |

第三種是我們想建立的態度。

## **三、其實這會形成一種很好的合作關係**

想像一下：

- 你不會，我不會。
- 我會，你不會。
- 你會，我不會。
- 我們都會，但看法不同。

如果大家都能坦然承認自己的限制，就不需要透過掩飾、推卸或責怪來保護自己。

而且，這裡還有一個重要觀念：

**問責不是要求每個人無所不知，而是要求每個人對自己不知道的事情，採取合理的行動。**

我覺得這已經延伸出一種很成熟的團隊文化：

**我們不要求彼此什麼都會，但要求彼此願意面對問題、尋找答案、共同承擔。**

這樣的團隊，反而更容易讓人願意承認錯誤、提出問題，也更容易真正學習。

# 靠要，那對方提出的問題，我不會。那我要去找答案? 不對吧?

哈哈，你抓到我前面回答的漏洞了！😂

對，為什麼對方提出問題，最後變成你要去找答案？

這其實又回到我們剛剛討論的「責任界線」。

**同理心不代表你要接手對方的問題，問責也不代表你必須替對方解決問題。**

## **正確的做法應該是：**

假設同事問你：

「這個 API 的某個欄位為什麼會回傳 null？你知道原因嗎？」

你不知道。

你可以回答：

「這個我不確定，你有查過 API 文件或問過 BE 嗎？」

如果對方還沒查，你可以引導他先查。

如果對方已經查過，仍然找不到答案，你們再討論是否需要一起找 BE 確認。

## **關鍵是區分三件事**

1. **聆聽問題**：我願意理解你遇到什麼困難。
2. **提供協助**：我可以提供我知道的資訊或協助你釐清方向。
3. **承擔責任**：不代表你的問題自動變成我的責任。

我認為這裡有一句話非常重要：

**我願意幫助你，但不代表我要替你負責。**

反過來也是一樣：

**我遇到問題，可以請你幫忙，但不代表你有義務替我解決。**

這才是真正對等的合作關係。

同理心是願意理解彼此，問責是各自承擔自己的責任。兩者不應該變成責任轉移的工具。
