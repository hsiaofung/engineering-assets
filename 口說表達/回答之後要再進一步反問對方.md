# 我發現一個溝通的方式，我之前問對方問題，對方回答完，或我回答完對方。就結束了，但我發現似乎要回答完對方後要再反問對方?

對！你發現了一個很重要的溝通技巧。

這其實涉及一個概念：**讓對話持續流動，而不是只完成一次問答。**

你之前的溝通模式可能是：

**原本的模式：問答式**

你

你問對方一個問題。

對方

對方回答。

結束

對話停止。

但你現在發現的模式是：

**新的模式：互動式**

你

你問對方問題。

對方

對方回答。

你

你回應他的答案，再提出一個相關問題。

對方

對方繼續分享。

你

你再接續話題。

### **舉個例子**

假設你問同事：

**你：** 週末去哪裡玩？

**對方：** 我去台中玩，逛了一些景點。

原本你可能回答：

「喔，台中不錯耶！」

然後就沒了。

但現在可以這樣：

**你：** 喔，台中不錯耶！你去了哪些景點？

**對方：** 去了審計新村，還吃了很多東西。

**你：** 審計新村我好像還沒去過耶！那邊有什麼值得推薦的嗎？

你看，對話就延續下去了。

### **但我想補充一個更重要的觀念**

不是每次回答完都一定要反問。

而是：

**回應對方 → 分享自己的想法 → 延伸話題 → 適時提問。**

例如：

- 回應：「原來如此！」
- 分享：「我之前也有類似的經驗。」
- 延伸：「不過我覺得這件事最有趣的是……」
- 提問：「那你當時怎麼決定的？」

這樣就不會變成一問一答的面試，而是真正的交流。

### **這也能解釋為什麼有些人特別會聊天**

他們不一定比較會說話，而是比較懂得接住對方提供的資訊，再把話題往前推進。

我甚至覺得可以把它當成一種可以刻意練習的 Skill：

**不要只負責回答問題，也要負責讓對話有下一步。**

這跟你之前提到英文對話時，常常不知道下一句要說什麼，其實也有關係。

你不需要每次都想一個全新的話題，只要從對方剛才說的內容，找到一個可以延伸的方向就好。

# 但也不是為了延續話題而一直反問吧? 而且我是在和同事討論工作上的問題。

沒錯！你這個修正很重要。

尤其你說的是**和同事討論工作問題**，那就不是單純的聊天技巧，而是工作上的溝通能力。

我認為重點不是「回答完一定要反問」，而是：

**回答完之後，不要讓溝通停留在單向資訊交換，而是確認雙方是否對事情有共同理解，以及接下來怎麼做。**

### **例如：你和 FE 討論一個 Bug**

**情境一：單純問答**

你：目前勾選的 System 在 polling 後會消失，這是預期行為嗎？

FE：是，因為 polling 會重新載入資料。

你：了解，謝謝。

對話結束。

這沒有錯，但問題可能還沒真正解決。

**情境二：有來有往的工作溝通**

你：目前勾選的 System 在 polling 後會消失，這是預期行為嗎？

FE：是，因為 polling 會重新載入資料。

你：了解，所以目前 polling 會清除使用者原本的選取狀態，對嗎？

FE：對。

你：那我們是否應該保留使用者原本選取的 System？因為使用者可能還要對這些 System 執行後續 Action。

FE：對，這樣比較合理，但目前共用元件好像沒有支援。

你：了解，那這部分可能需要調整共用元件，還是有其他方式可以處理？

你看，這裡的提問不是為了延續對話，而是為了推進問題。

### **我會把工作溝通分成四個層次**

| 層次    | 目的        | 例子                  |
| ----- | --------- | ------------------- |
| 1. 詢問 | 取得資訊      | 這是預期行為嗎？            |
| 2. 確認 | 確保理解正確    | 所以 polling 會清除選取狀態？ |
| 3. 探討 | 找出問題與可能方案 | 是否應該保留選取狀態？         |
| 4. 推進 | 確定下一步     | 那我們要怎麼處理？           |

不一定每次都要走完四個層次，視問題複雜度而定。

### **我覺得你真正發現的是一件事**

以前你的溝通可能比較偏向：

「我有問題 → 我問你 → 你回答 → 我取得答案。」

現在可以進一步變成：

「我有問題 → 我問你 → 你回答 → 我理解並確認 → 我提出想法 → 我們共同找到解決方式。」

這兩者有很大的差別。

前者是資訊交換，後者是協作。

**好的工作溝通，不是讓對話一直持續，而是讓每一次互動都能讓雙方更接近問題的解決。**
